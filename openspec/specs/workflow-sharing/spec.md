# workflow-sharing Specification

## Purpose
Safe, review-first workflow bundle export and import without workflow execution.

## Requirements
### Requirement: Workflow export produces a connected bundle command
The picker share action MUST export the exact selected `repo` or `global` workflow, and every transitively referenced workflow, as a gzip-compressed, base64-encoded JSON array of `{name, yaml}` entries. It MUST copy `hwf workflow import "<bundle>"` to the clipboard as the primary sharing artifact. The bundle MUST contain no version, root, source, configuration, or non-workflow metadata.

#### Scenario: Export selected source
- **WHEN** a user shares repo workflow `handoff` from the picker palette
- **THEN** the generated bundle contains `{name: "handoff", yaml: <exact repo workflow body>}` and the clipboard holds the import command

#### Scenario: Export invalid workflow
- **WHEN** the selected source does not parse as a supported workflow
- **THEN** export fails with the validation error instead of producing a command

#### Scenario: Transitive mixed-source children
- **WHEN** the selected workflow references a repo child that references a global child
- **THEN** export includes all three exact workflow bodies once using the runtime's repo-first resolution

#### Scenario: Missing child
- **WHEN** an exported workflow transitively references a workflow that cannot be resolved
- **THEN** export fails and names the missing workflow instead of producing a partial bundle

#### Scenario: Workflow cycle
- **WHEN** the selected workflow's transitive graph contains a cycle
- **THEN** export fails with the workflow cycle instead of producing a bundle

#### Scenario: Provenance is display-only
- **WHEN** export resolves workflows from repo and global storage
- **THEN** the picker can identify those local sources but the encoded array contains only names and YAML

### Requirement: Import preview accepts only canonical sharing input
`hwf workflow import` MUST accept a raw encoded bundle or the exact generated import-command shape. It MUST extract a bundle without evaluating a shell command. It MUST reject unrelated command text, malformed encodings, empty arrays, duplicate or invalid names, empty YAML, unsupported workflow syntax, and any non-array payload shape. It MUST NOT accept a filesystem path, stdin YAML body, or `--name` as a substitute for a bundle.

#### Scenario: Generated command pasted
- **WHEN** a user runs a command generated by workflow export
- **THEN** the CLI decodes and validates every bundled workflow without executing the command

#### Scenario: Shell text pasted
- **WHEN** a user passes command text outside the canonical import-command shape and the text is not a bundle
- **THEN** the CLI rejects it without invoking a shell

#### Scenario: Non-array payload pasted
- **WHEN** a user passes a single-object sharing payload instead of the array bundle
- **THEN** the CLI rejects it

### Requirement: Import requires complete review and explicit consent
Before writing a bundle, `hwf workflow import` MUST display every workflow name, every complete YAML body, aggregate sensitivity warnings, and any references not present in the bundle. It MUST require one explicit `repo` or `global` destination for all entries, and it MUST require confirmation on a TTY. Preview and import MUST never execute workflows, resolve external child workflows, or run dynamic-choice commands.

#### Scenario: Sensitive workflow preview
- **WHEN** a valid payload contains shell commands or sensitive workflow behavior
- **THEN** the import preview displays the complete YAML and corresponding warning before enabling confirmation

#### Scenario: User cancels import
- **WHEN** a user reviews a payload but does not confirm
- **THEN** no workflow file is written

#### Scenario: Confirm repo import
- **WHEN** a user selects repo, reviews the workflow, and confirms an unused destination
- **THEN** every exact bundled YAML body is written to `.hwf/workflows/<name>.yaml`

### Requirement: Existing workflow replacement is separately confirmed
Import MUST validate and preflight the complete bundle before writing any destination, and it MUST preserve the complete existing set by default. If the chosen scope already contains any bundled name, the CLI MUST identify all conflicts and require `--force` before writing the bundle. An import MUST leave the destination scope either wholly as the reviewed bundle or wholly as it was before, including across process death.

#### Scenario: Existing destination kept
- **WHEN** any bundled workflow name already exists and the user does not pass `--force`
- **THEN** no bundled destination is written and every existing file remains unchanged

#### Scenario: Existing destination replaced
- **WHEN** bundled workflow names already exist and the user passes `--force` after review
- **THEN** every bundle entry is written to the selected scope using its reviewed YAML

### Requirement: Sharing never runs workflows
Share and import MUST provide no action that executes the exported, previewed, or imported workflow.

#### Scenario: Import completes
- **WHEN** a workflow is imported successfully through the CLI
- **THEN** the CLI reports the written paths without running the workflow
