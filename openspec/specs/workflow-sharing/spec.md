# workflow-sharing Specification

## Purpose
Safe, review-first workflow bundle export and import without workflow execution.

## Requirements
### Requirement: Workflow export produces a connected bundle command
The workbench MUST export the exact selected `repo` or `global` workflow, and every transitively referenced workflow, as a gzip-compressed, base64-encoded JSON array of `{name, yaml}` entries. It MUST present `hwf workflow import "<bundle>"` as the primary sharing artifact. The bundle MUST contain no version, root, source, configuration, or non-workflow metadata.

#### Scenario: Export selected source
- **WHEN** a user opens sharing for repo workflow `handoff`
- **THEN** the generated bundle contains `{name: "handoff", yaml: <exact repo workflow body>}`

#### Scenario: Export invalid workflow
- **WHEN** the selected source does not parse as a supported workflow
- **THEN** export fails with the validation error instead of producing a command

#### Scenario: Transitive mixed-source children
- **WHEN** the selected workflow references a repo child that references a global child
- **THEN** export includes all three exact workflow bodies once using the runtime's repo-first resolution

#### Scenario: Missing child
- **WHEN** an exported workflow transitively references a workflow that cannot be resolved
- **THEN** export fails and names the missing workflow instead of producing a partial bundle

#### Scenario: Workflow cycle
- **WHEN** the selected workflow's transitive graph contains a cycle
- **THEN** export fails with the workflow cycle instead of producing a bundle

#### Scenario: Provenance is display-only
- **WHEN** export resolves workflows from repo and global storage
- **THEN** the share view can identify those local sources but the encoded array contains only names and YAML

### Requirement: Import preview accepts only canonical sharing input
The workbench import view MUST accept a raw encoded bundle, the exact generated import-command shape, or a single raw workflow YAML document. It MUST extract a bundle without evaluating a shell command. For bundle or command input, it MUST reject unrelated command text, malformed encodings, empty arrays, duplicate or invalid names, empty YAML, unsupported workflow syntax, and any non-array payload shape other than a single workflow YAML document. For raw YAML, it MUST schema-parse the document without executing workflows or dynamic-choice commands, and it MUST require an explicit workflow name before confirm (name MUST match the workflow name grammar). Preview of raw YAML MUST present that single entry for review like a one-entry bundle. Freeform raw YAML MUST be workbench-only; the CLI import command MUST continue to accept only the bundle or generated import-command shape.

#### Scenario: Generated command pasted
- **WHEN** a user pastes a command generated by workflow export
- **THEN** the workbench decodes and validates every bundled workflow without executing the command

#### Scenario: Shell text pasted
- **WHEN** a user pastes command text outside the canonical import-command shape and the text is not workflow YAML
- **THEN** the workbench rejects it without invoking a shell

#### Scenario: Non-array payload pasted
- **WHEN** a user pastes a single-object sharing payload instead of the array bundle or workflow YAML
- **THEN** the workbench rejects it

#### Scenario: Raw YAML pasted in workbench
- **WHEN** a user pastes a valid `v1alpha1` workflow YAML document in the workbench import view and supplies name `mine`
- **THEN** the import preview shows one entry named `mine` with that YAML body and does not execute the workflow

#### Scenario: Raw YAML without name
- **WHEN** a user pastes valid workflow YAML but does not supply a workflow name
- **THEN** confirm import remains unavailable until a valid name is provided

### Requirement: Import requires complete review and explicit consent
Before writing a bundle, the workbench MUST display every workflow name, every complete YAML body, aggregate sensitivity warnings, and any references not present in the bundle. It MUST require one explicit `repo` or `global` destination for all entries, and it MUST require confirmation. Preview and import MUST never execute workflows, resolve external child workflows, or run dynamic-choice commands.

#### Scenario: Sensitive workflow preview
- **WHEN** a valid payload contains shell commands or sensitive workflow behavior
- **THEN** the import view displays the complete YAML and corresponding warning before enabling confirmation

#### Scenario: User cancels import
- **WHEN** a user reviews a payload but does not confirm
- **THEN** no workflow file is written

#### Scenario: Confirm repo import
- **WHEN** a user selects repo, reviews the workflow, and confirms an unused destination
- **THEN** every exact bundled YAML body is written to `.hwf/workflows/<name>.yaml`

### Requirement: Existing workflow replacement is separately confirmed
Import MUST validate and preflight the complete bundle before writing any destination, and it MUST preserve the complete existing set by default. If the chosen scope already contains any bundled name, the workbench MUST identify all conflicts and require one separate explicit replace-all confirmation before writing the bundle. An import MUST leave the destination scope either wholly as the reviewed bundle or wholly as it was before, including across process death.

#### Scenario: Existing destination kept
- **WHEN** any bundled workflow name already exists and the user does not confirm replacement
- **THEN** no bundled destination is written and every existing file remains unchanged

#### Scenario: Existing destination replaced
- **WHEN** bundled workflow names already exist and the user explicitly confirms replace-all
- **THEN** every bundle entry is written to the selected scope using its reviewed YAML

### Requirement: Workbench sharing never runs workflows
Share and import views MUST provide no action that executes the exported, previewed, or imported workflow.

#### Scenario: Import completes
- **WHEN** a workflow is imported successfully
- **THEN** the workbench reports the saved workflow without running it
